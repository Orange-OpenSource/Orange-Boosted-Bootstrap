This guide provides information on how to migrate from OB1 (latest release of v2) to OUDS Web, with Bootstrap compatibility turned off. [Learn more about Bootstrap compatibility]([[docsref:/foundation/approach#bootstrap-compatibility]]).

<Callout type="info">
  The [`@ouds/web-migrate`](https://www.npmjs.com/package/@ouds/web-migrate) CLI can help migrate from OB1 to OUDS Web. Run it against your project files and review the diff afterward:

  ```bash
  npx @ouds/web-migrate --from=ob1 "src/**/*.{css,scss,html,vue}"
  ```

  The CLI automatically replaces some classes and only emits a warning for others. Warnings point to components or classes that require a manual migration: please review them carefully.
</Callout>

Let’s start with the most obvious change you’ll notice: the name. **OB1 is now OUDS Web.**

- The NPM packages are now `@ouds/web-common` and `@ouds/web-orange` or `@ouds/web-sosh` depending on brand used.
- The CSS and JS files have been renamed:
  - `style.css` → `ouds-web.css` in package related to brand used
  - `style.min.css` → `ouds-web.min.css` in package related to brand used
  - `ob1.bundle.js` → `ouds-web.bundle.js` in `@ouds/web-common`
  - `ob1.bundle.min.js` → `ouds-web.bundle.min.js` in `@ouds/web-common`
  - `ob1.esm.js` → `ouds-web.esm.js` in `@ouds/web-common`
  - `ob1.esm.min.js` → `ouds-web.esm.min.js` in `@ouds/web-common`
  - `ob1.js` → `ouds-web.js` in `@ouds/web-common`
  - `ob1.min.js` → `ouds-web.min.js` in `@ouds/web-common`
- The `flags.css` file together with the minified version have been removed, you could directly use the [flag-icons npm package](https://www.npmjs.com/package/flag-icons)
- All fonts-icons file have been removed, read more about [managing icons](([[docsref:/foundation/icons]]))

From now on, OUDS Web won’t embed Bootstrap elements that are not part of Orange Unified Design System. However, you can still use our Bootstrap compatibility mode by using `ouds-web-bootstrap.css` and `ouds-web-bootstrap.min.css`.

## Foundations

- <span class="tag tag-small tag-warning"><span class="tag-status-icon"></span>Warning</span> Orange color has been modified from `#f16e00` to `#f15e00`. It means that under certain circumstances, you might be able to use Orange and light gray items together.

- <span class="tag tag-small tag-positive"><span class="tag-status-icon"></span>New</span> We provide four color mode allowinf you to handle Dark mode in every situation. See more on our [color modes page]([[docsref:/foundation/color-modes]])

- <span class="tag tag-small tag-warning"><span class="tag-status-icon"></span>Warning</span> The root selector have been tweaked and can be customized for more flexibility on JS frameworks. Please don’t hesitate to contact us if you find any issue with it.

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> The focus-visible polyfill has been removed. So you no longer need it on your side, and you should replace all the calls to `:focus[data-focus-visible-added]` by `:focus-visible`.

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> jQuery support has been removed from the library.

## Fonts

OUDS Web doesn’t provide Helvetica Neue font files. Instead, it loads the font from a CDN in order to share the cached files between every project using OUDS Web.

Technically, it means that you can get rid of the following things:
- Helvetica Neue woff2 files: `fonts/HelvNeue55_W1G.woff2` and `fonts/HelvNeue75_W1G.woff2`.
- If you were customizing your Sass compilation, you can remove the `@import "boosted/orange-helvetica";` line from your Sass files if it was there.

Read more about the [font stack]([[docsref:/foundation/reboot#font-stack]]) for more details.

## Content styles

### Typography

- <span class="tag tag-small tag-positive"><span class="tag-status-icon"></span>New</span> Body 1, Body 2 and Caption are now named body large, body medium and body small. See [Typography]([[docsref:/foundation/typography/#regular-texts]]) for more details.

- <span class="tag tag-small tag-positive"><span class="tag-status-icon"></span>New</span> A `max-width` has been added on all font references for readability reasons. If you want to get rid of the `max-width`, please use our `.mw-none` width utility.

- <span class="tag tag-small tag-positive"><span class="tag-status-icon"></span>New</span> Selected text is now styled with a specific text `color` and `background-color`, making it easier to spot and to read.

- <span class="tag tag-small tag-positive"><span class="tag-status-icon"></span>New</span> Display headings classes `.display-{small|medium|large}` have been added.

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> Abbreviation class `.initialism` has been removed.

- <span class="tag tag-small tag-warning"><span class="tag-status-icon"></span>Warning</span> Default spacing values now use `px`s instead of `em`s for fixed component spacing, to keep as much space as possible for meaningful content on zoom. The bottom margin of headings is now set to token `$ouds-space-fixed-medium` (16px on Orange brand)

## Layout

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> Responsive breakpoints have changed:
  - `2xs` and `3xl` have been added.
  - `xxl` has been renamed to `2xl`.
  - The breakpoints values have changed. Please refer to the [breakpoints’ documentation]([[docsref:/layout/breakpoints]]).
  - The default container to use is `.container-fluid` associated to `.container-max-width` instead of using `.site-width` as parent. Please refer to the [fluid containers’ documentation]([[docsref:/layout/containers#fluid-containers]]). The security margin value has changed.
  - Default gutter inside grid has been changed to have a fully responsive behavior. It should be a pretty transparent change for you.
  - All gutter utilities have been changed. `.g{-breakpoint}-{value}`, `.gx{-breakpoint}-{value}` and `.gy{-breakpoint}-{value}` which value is inside `0|1|2|3|4|5`. Gutter utilities values now use `none|3xsmall|2xsmall|xsmall|small|medium|large|xlarge|2xlarge|3xlarge|4xlarge|5xlarge`. Proportional equivalence between `0` → `none`, `1` → `medium`, `2` → `xlarge`, `3` → `3xlarge`, `4` → `4xlarge`, `5` → `5xlarge`.

All responsive classes, helpers, and utilities have been updated accordingly to match the new breakpoints.

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> All responsive utility classes now use a **Tailwind-style colon prefix** instead of Bootstrap's dash infix. The pattern `.{utility}-{breakpoint}-{value}` becomes `.{breakpoint}:{utility}-{value}` for all breakpoints (`xs`, `sm`, `md`, `lg`, `xl`, `2xl`, `3xl`). The `2xs` breakpoint (the smallest) has no prefix and is unchanged. Read more in our [breakpoints page]([[docsref:/layout/breakpoints]]).

- <span class="tag tag-small tag-info"><span class="tag-status-icon"></span>Info</span> `.container` and `.container-{breakpoint}` have been removed from the default build but you can still have them using `$enable-bootstrap-compatibility`.
- <span class="tag tag-small tag-info"><span class="tag-status-icon"></span>Info</span> `xxl` breakpoint and thus all related classes (like `.container-xxl`, `.col-xxl-*`) can still be available when `$enable-bootstrap-compatibility` is enabled.

## Icons

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> OUDS Web now uses [new functional icons]([[docsref:/foundation/icons#functional-icons]]). A new [bicolor accessible warning icon]([[docsref:/foundation/icons#accessible-warning-icon]]) has been introduced.

### Alerts

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> The DOM for alerts has changed a lot so we recommend to read our [new alerts page]([[docsref:/components/alerts]]) first.
    <details class="mb-medium">
      <summary>See all changing classes</summary>

      - `.alert` → `.alert.alert-message` (for the block variant with a container and an optional action) or `.alert` alone (for the inline variant).
      - `.ob1-alert-title` → `.alert-label`.
      - `.alert-content` → `.alert-text-container` (block variant).
      - `.alert-icon` → Stays the same, but must now contain a `<p class="visually-hidden">` (or an equivalent hidden text) describing the alert status instead of relying only on the icon.
      - `.alert-container` is now mandatory around `.alert-icon` and `.alert-text-container` for the block variant (in OB1, `.alert-container` only wrapped `.alert` and `.alert-content`).
      - `additional-message` (OB1 neutral variant) → `.alert-message` without a status modifier, or `.alert-neutral` depending on the context.
      - `.alert-success` → `.alert-positive`.
      - `.alert-danger` → `.alert-negative`.
      - `.alert-info` and `.alert-warning` stay the same.
      - `.alert-heading` → `.alert-label`.
      - `.alert-sm` and `.alert-dismissible` must be removed.

      The CLI only replaces `.alert` (→ `.alert.alert-message`), `.alert-danger`, `.alert-success` and `.alert-heading`. All the other changes, including `.ob1-alert-title`, `.alert-content` and `.alert-icon`, and the OB1 in-line suggestion (`.ob1-inline-suggestion`), must be done manually.

    </details>
- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> OB1's In-page alert (`.feedback`, `.feedback-title`, `.feedback-text`, `.feedback-button`) doesn't have a direct documented equivalent in OUDS Web yet. Please rely on the [alerts documentation]([[docsref:/components/alerts]]) and adapt the block alert variant to your layout in the meantime.
- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> Actions inside an alert (buttons, chevron links, expand links) must now be placed the same way as documented, using the standard [buttons]([[docsref:/components/buttons]])/[links]([[docsref:/components/links]]) classes instead of OB1's `.ob1-link-arrow`.

### List items

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> List item is a new component compared to OB1's List item, the DOM is therefore very different. See our [new Items page]([[docsref:/components/items]]) first.
<div class="ps-xlarge">
For example, if you used to write:

```html
<ul class="items-list row">
  <li class="col-12 col-md-6 col-xl-4">
```

```html
<ul class="item-list">
  <li class="item item-navigation">
    <div class="item-container">

          <a href="#" class="item-label item-interactive">Label</a>

        </div>
      </div>
    </div>
  </li>
</ul>
```
See [our new Items page]([[docsref:/components/items]]) for more information.
</div>

#### Checkbox

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> Checkbox is a new component compared to OB1’s Check, the DOM is therefore different.
<div class="ps-xlarge">
For example, if you used to write:

```html
<ul class="items-list">
  <li>
    <div class="items-list-item">
      <div class="item-container item-container-sm">
        <div class="form-check">
          <input
            type="checkbox"
            aria-labelledby="customControlLabelValidation1"
            class="form-check-input"
            id="customControlValidation1"
            checked
          />
          <label aria-hidden="true" class="form-check-label" for="customControlValidation1"></label>
        </div>
        <label id="customControlLabelValidation1" for="customControlValidation1" class="item-text"> Label </label>
      </div>
    </div>
  </li>
</ul>
```
Now you should write:

```html
<fieldset class="control-items-list">
  <div class="checkbox-item">
    <div class="control-item-assets-container">
      <input class="control-item-indicator" type="checkbox" value="" id="checkboxDefault" checked />
    </div>
    <div class="control-item-text-container">
      <label class="control-item-label" for="checkboxDefault">Label</label>
    </div>
  </div>
</fieldset>
```
See [our new Checkbox page]([[docsref:/components/checkbox]]) for more information.
</div>

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> The error management is different from OB1's, it is now based on `:user-invalid` pseudo class or `aria-invalid` attribute. The DOM structure must also be updated for the error message. Read more in the [checkbox documentation]([[docsref:/components/checkbox/#invalid]]) for more details.

## Sass

- <span class="tag tag-small tag-positive"><span class="tag-status-icon"></span>New</span> The mixin `get-font-size({font-size-ref})` has been added, where `font-size-ref` is one of: `"code-medium"`, `"label-small"`, `"label-medium"`, `"label-large"`, `"label-xlarge"`, `"body-small"`, `"body-medium"`, `"body-large"`, `"heading-small"`, `"heading-medium"`, `"heading-large"`, `"heading-xlarge"`, `"display-small"`, `"display-medium"`, `"display-large"`. If you have/need any `font-size` in one of your SCSS classes, please consider using this mixin instead. See [Typography Sass mixins]([[docsref:/foundation/typography#sass-mixins]]) for more details.

- <span class="tag tag-small tag-warning"><span class="tag-status-icon"></span>Warning</span> `color-mode({mode}, {root}, {inverted-mode})` mixin signature has changed. We now provide an `$inverted-mode` parameter that is set by default to `light` or `dark` depending on the `$mode`. It allows you to precise another mode to be the inverse of a certain mode.

- <span class="tag tag-small tag-warning"><span class="tag-status-icon"></span>Warning</span> `button-variant` mixin signature has changed. We now provide extra parameters for focus and loading states colors. We keep it as a warning because we provide default values for these parameters. See more in [our Button documentation]([[docsref:/components/buttons#sass-mixins]]).

- <span class="tag tag-small tag-negative"><span class="tag-status-icon"></span>Breaking</span> `add` and `subtract` functions have been removed use `calc` instead.

- <span class="tag tag-small tag-info"><span class="tag-status-icon"></span>Info</span> The `list-unstyled` mixin has been updated to remove the list margin bottom.
