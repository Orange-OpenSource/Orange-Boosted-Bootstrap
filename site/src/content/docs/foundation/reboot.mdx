## Approach

Reboot is a shared SCSS file imported after the root styles and before typography, layout, and component styles in each [theme]([[docsref:/foundation/themes]]) stylesheet. This order sets the basic styles first, later styles can then build on or override them.

Reboot builds on Normalize and sets default styles using element selectors. For example, Reboot resets the default styling of lists, while the [Bullet list component]([[docsref:/components/bullet-list]]) offers more stylised lists using classes such as `.bullet-list` or `.bullet-list-default-color`.

Reboot follows these guidelines:

- Use `px` instead of `em` for fixed spacing, so zoom leaves more room for content.
- Avoid `margin-top`. Vertical margins can collapse; using only one margin direction keeps spacing predictable.
- Use `px` margins on block elements to make spacing consistent across screen sizes.
- Set as few font properties as possible and use `inherit` where possible.
- Text has a `max-width` for readability. Remove it with the `.mw-none` [width utility]([[docsref:/utilities/sizing]]) when needed.

### CSS variables

Every OUDS Web (like `ouds-web.css`, `ouds-web-reboot.css`, or `ouds-web-grid.css`) CSS bundle includes `_root.scss`, which defines root-level [CSS variables]([[docsref:/foundation/css-variables]]) (also called custom properties). These variables are generated from Sass variables, so you can customize styles with Sass at build time or with CSS variables at runtime.

### Page defaults

Reboot sets consistent defaults for the page:

- Every element, including `*::before` and `*::after`, uses `box-sizing: border-box`. Padding and borders are included in the declared width.
- Reboot does not set a font size on `<html>`, so `1rem` follows the browser default (usually `16px`) and respects user preferences. Direct children of the root use `font-size: 1rem`. Set a new `$font-size-root` to override the browser default.
- Direct children of the root receive the base `font-family`, `font-weight`, `line-height`, `color`, and `background-color`.

### Font stack
OUDS Web loads custom brand fonts from a CDN, to ensure optimum text rendering on every device and OS, and to benefit from the browser's cache.

If a custom font is unavailable, OUDS Web uses a system font stack for clear text rendering across devices. The stack is defined here:

Font-face rules are generated in `_root.scss` from the `$custom-font-cdn-urls` map. Update the URLs if you host the fonts elsewhere.

## Links

Links have bold and underline applied. While links change on `:hover`, by default they don’t change based on whether someone `:visited` the link.

<Example buttonLabel="link" code={`<a href="#">This is an example link</a>`} />

Links have a disabled style when using an `aria-disabled="true"` attribute.

<Example buttonLabel="disabled link" code={`<a aria-disabled="true">This is an example of a disabled link</a>`} />

Visited links don’t have a specific style by default.

<ThemeSpecific theme={['orange', 'orange-compact']}>
The `:visited` state can be styled with the additional `.visited-links` utility class that can be applied directly to a link or to a parent element to style all the child links.

<Example buttonLabel="visited link" code={`<div class="visited-links">
    <div>
      <a href=".">This is an example of a visited link</a>
    </div>
    <div>
      <a href="#">This is an example of an unvisited link</a>
    </div>
  </div>
  <div>
    <a href="." class="visited-links">This is an example of a visited link</a>
  </div>`} />
</ThemeSpecific>

Placeholder links—those without an `href`—are targeted with a more specific selector and have their `color` and `text-decoration` reset to their default values.

<Example buttonLabel="placeholder link" code={`<a>This is a placeholder link</a>`} />

On colored backgrounds, links should have a different style. Visited links don’t have a specific style on colored backgrounds.

## Inline text elements

Styling for common inline HTML5 elements.

<Example code={`<p>You can use the mark tag to <mark>highlight</mark> text.</p>
<p><del>This line of text is meant to be treated as deleted text.</del></p>
<p><s>This line of text is meant to be treated as no longer accurate.</s></p>
<p><ins>This line of text is meant to be treated as an addition to the document.</ins></p>
<p><u>This line of text will render as underlined.</u></p>
<p><small>This line of text is meant to be treated as fine print.</small></p>
<p><strong>This line rendered as bold text.</strong></p>
<p><em>This line rendered as bold text too,</em> but would natively be italicized.</p>`} />

Beware that those tags should be used for semantic purpose:

- `<mark>` represents text which is marked or highlighted for reference or notation purposes.
- `<small>` represents side-comments and small print, like copyright and legal text. It uses [Regular text](#regular-texts) body small.
- `<s>` represents element that are no longer relevant or no longer accurate.
- `<u>` represents a span of inline text which should be rendered in a way that indicates that it has a non-textual annotation.

If you want to style your text, you should use the following classes instead:

- `.mark` will apply the same styles as `<mark>`.
- `.small` will apply the same styles as `<small>`.
- `.text-decoration-underline` will apply the same styles as `<u>`.
- `.text-decoration-line-through` will apply the same styles as `<s>`.

While not shown above, feel free to use `<b>` and `<i>` in HTML5. `<b>` is meant to highlight words or phrases without conveying additional importance, while `<i>` is mostly for voice, technical terms, etc.

## Forms

Various form elements have been rebooted for simpler base styles. Here are some of the most notable changes:

- `<fieldset>`s have no borders, padding, or margin so they can be easily used as wrappers for individual inputs or groups of inputs.
- `<legend>`s, like fieldsets, have also been restyled to be displayed as a heading of sorts.
- `<label>`s are set to `display: inline-block` to allow `margin` to be applied.
- `<input />`s, `<select>`s, `<textarea>`s, and `<button>`s are mostly addressed by Normalize, but Reboot removes their `margin` and sets `line-height: inherit`, too.
- `<textarea>`s are modified to only be resizable vertically as horizontal resizing often "breaks" page layout.
- `<button>`s and `<input />` button elements have `cursor: pointer` when `:not(:disabled)`.

## Address

The `<address>` element is updated to reset the browser default `font-style` from `italic` to `normal`. `line-height` is also now inherited, and <code>margin-bottom: {getTokenValue('$ouds-space-fixed-medium')}</code> has been added. `<address>`s are for presenting contact information for the nearest ancestor (or an entire body of work). ## Blockquote

For quoting blocks of content from another source within your document, wrap `<blockquote>` around any HTML as the quote. The default `margin` on blockquotes is `1em 40px`, so we reset that to <code>0 0 {getTokenValue('$ouds-space-fixed-medium')}</code> for something more consistent with other elements. `<blockquote>` uses [Regular text](#regular-texts) body large. {/* TODO change the link */}

<Example code={`<blockquote>
    <p>A well-known quote, contained in a blockquote element.</p>
  </blockquote>`} />

### Naming a source

The HTML spec requires that blockquote attribution be placed outside the `<blockquote>`. When providing attribution, wrap your `<blockquote>` in a `<figure>` and use a `<figcaption>` or a block level element (e.g., `<p>`) with the `.blockquote-footer` class. Be sure to wrap the name of the source work in `<cite>` as well. It uses [Regular text](#regular-texts) body small.

<Example code={`<figure>
    <blockquote>
      <p>A well-known quote, contained in a blockquote element.</p>
    </blockquote>
    <figcaption class="blockquote-footer">
      Someone famous in <cite title="Source Title">Source Title</cite>
    </figcaption>
  </figure>`} />

## HTML5 `[hidden]` attribute

HTML5 adds [a new global attribute named `[hidden]`](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/hidden), which is styled as `display: none` by default. Borrowing an idea from [PureCSS](https://purecss.io/), we improve upon this default by making `[hidden] { display: none !important; }` to help prevent its `display` from getting accidentally overridden.

<Code lang="html" buttonLabel="hidden attribute" code={`<input type="text" hidden />`} />

To merely toggle the visibility of an element, meaning its `display` is not modified and the element can still affect the flow of the document, use [the `.invisible` class]([[docsref:/utilities/visibility]]) instead.
