## [[comp]] Switch item

Switch item is a UI element shaped like a row that toggles between two states, typically "On" and "Off," and is used to enable or disable features, options, or settings.

Unlike the [standalone switch](#switch), the switch item accommodates a broader range of contexts by enabling the toggling of visibility of additional text labels and icon assets.

They are implemented using `.switch-item` and `.control-item-*` classes, [see below](#control-item). Browser default checkboxes are replaced with the help of `.control-item-indicator[role="switch"]`.

<Example buttonLabel="basic switch items" code={`<ul class="control-items-list">

    <li class="switch-item">
      <div class="control-item-assets-container">
        <input class="control-item-indicator" type="checkbox" role="switch" value="" id="switchItemDefault" />
      </div>
      <div class="control-item-text-container">
        <label class="control-item-label" for="switchItemDefault">Default switch item</label>
      </div>
    </li>

    <li class="switch-item">
      <div class="control-item-assets-container">
        <input checked class="control-item-indicator" type="checkbox" role="switch" value="" id="switchItemDefault2" />
      </div>
      <div class="control-item-text-container">
        <label class="control-item-label" for="switchItemDefault2">Checked switch item</label>
      </div>
    </li>

  </ul>`} />

### Approach

#### Control item

<ControlItem />

#### Switch grouping and error handling

As switch items can be used inside a list or a form, but also in a standalone way, there are several ways to group them. You can use a `<fieldset>` container if they are in a form, with an optional `<legend>` ([read more here](#fieldset-legend)), you can also use a `<ul>` (like most of the examples in this page). For both these solutions please add a `.control-items-list` class on the list container.

For automatic error handling on a single switch item, you need to surround it in a `.switch-item-container`, read more in the [invalid state section](#invalid).

#### Read only

To create a read only switch item, the input should be replaced by a `span` element with `role="switch"`, `aria-readonly="true"` and `aria-disabled="true"` attributes. The switch item will be accessible to keyboard navigation and assistive technologies thanks to `aria-labelledby` and `tabindex`, but other interactions will be prevented.

<Example buttonLabel="readonly switch items" code={`<ul class="control-items-list">

    <li class="switch-item">
      <div class="control-item-assets-container">
        <span class="control-item-indicator" role="switch" aria-readonly="true" aria-disabled="true" tabindex="0" aria-checked="false" aria-labelledby="switchItemReadonlyLabel"></span>

#### Invalid

<Callout type="info" name="input-invalid" />

<Callout title="Prefer built-in form validation to handle client-side validation" type="info" name="form-field-validation" />

To manually mark a switch item as invalid, add `aria-invalid="true"` to a `.control-item-indicator`. An error icon will be automatically shown; if a decorative icon is specified, it will be hidden.

### Fieldset `<legend>`

For accessibility reasons, it is required to provide understandable switch item labels without relying on visual context. If switch items belong to a group, it is good practice to add a group title inside a `<legend>` element as the first child of the `<fieldset>` element. Screen readers will read the legend before navigating through the switch items; this way, keyboard navigation users have more information on what is expected with the multiple switch items element.

## [[comp]] Switch

Switch is a UI element that toggles between two states, typically "On" and "Off," and is used to enable or disable features, options, or settings.

Switch, that lacks an additional icon asset or text label, provides greater flexibility when creating other components that require a switch.

<Callout type="warning" name="standalone-form-indicator" />

For the standalone switch, we provide a completely different architecture than switch item to ease the integration inside your projects.

<Example buttonLabel="switch" code={`<label class="switch-standalone">
    <input class="control-item-indicator" type="checkbox" role="switch" value="" />
    <span class="visually-hidden">Switch</span>
  </label>`} />

### States

#### Disabled

Add the `disabled` attribute to prevent interaction with the switch and remove it from the keyboard tab order.

<Example buttonLabel="disabled standalone switch" code={`<label class="switch-standalone">
    <input disabled class="control-item-indicator" type="checkbox" role="switch" value="" />
    <span class="visually-hidden">Disabled switch</span>
  </label>`} />

#### Read only

Switch inputs do not support the `readonly` attribute. Replace the input with an element that has `role="switch"`, `aria-readonly="true"`, `aria-disabled="true"`, `aria-checked`, and `tabindex="0"`.

<Example buttonLabel="readonly standalone switch" code={`<span class="switch-standalone">
    <span class="control-item-indicator" role="switch" aria-readonly="true" aria-disabled="true" tabindex="0" aria-checked="true" aria-label="Read only switch"></span>
  </span>`} />

#### Invalid

<Callout title="Prefer built-in form validation to handle client-side validation" type="info" name="form-field-validation" />

To manually mark a switch as invalid, add `aria-invalid="true"` to the input and use `aria-describedby` to associate an error message with it.

<Callout type="warning" name="control-standalone-invalid-no-icon" />

<Example buttonLabel="invalid standalone switch" code={`<div>
    <label class="switch-standalone">
      <input class="control-item-indicator" type="checkbox" role="switch" value="" aria-invalid="true" aria-describedby="switchStandaloneError" />
      <span class="visually-hidden">Switch</span>
    </label>
    <p id="switchStandaloneError">This setting cannot be enabled.</p>
  </div>`} />

## Native switches

Progressively enhance your switches for mobile Safari (iOS 17.4+) by adding a `switch` attribute to your input to enable haptic feedback when toggling switches, just like native iOS switches. There are no style changes attached to using this attribute in OUDS Web as all our switches use custom styles.

<Example buttonLabel="native switch" code={`<div class="switch-item">
    <div class="control-item-assets-container">
      <input class="control-item-indicator" type="checkbox" role="switch" value="" id="switchNative" switch />
    </div>
    <div class="control-item-text-container">
      <label class="control-item-label" for="switchNative">Native switch haptics</label>
    </div>
  </div>`} />

Be sure to read more about [the switch attribute on the WebKit blog](https://webkit.org/blog/15054/an-html-switch-control/). Safari 17.4+ on macOS and iOS both have native-style switches in HTML while other browsers simply fall back to the standard checkbox appearance. Applying the attribute to a non-OUDS Web checkbox in more recent versions of Safari will render a native switch.
