### Approach

Modal dialog and fullscreen dialog use the same native `<dialog>` element with the `.modal-base` class and the same internal structure with `.modal-header`, `.modal-body`, and `.modal-footer`. Either use `.modal-dialog` for a standard modal dialog or `.modal-fullscreen-dialog` for a fullscreen modal.

The [common variants](#common-variants) are shared between modal dialog and fullscreen dialog, modal dialog has [specific variants](#variants) and [sizes](#sizes).

As this component relies on the native `<dialog>` element we encourage you to read the [MDN documentation on the `<dialog>` element](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/dialog).

### Accessibility

As we use the native `<dialog>` element, we benefit from built-in accessibility features such as keyboard navigation, focus management, and screen reader support.

Some things to keep in mind while using modals include:
- Ensure that the dialog has a meaningful and descriptive title, use the `[aria-labelledby]` attribute to reference the title element.
- Choose the most appropriate initial focus when the dialog opens. By default, focus moves to the first focusable element; use `[autofocus]` when another element, such as the close button or an input, should receive focus.
- Always provide an explicit and accessible way to close the dialog, such as a close, cancel, or confirmation button. Modal dialogs should also preserve the default `Escape` key behavior.
- Open modal dialogs [with `showModal()`](#javascript) or the [`show-modal` invoker command](#invoker-commands) so that the rest of the page is made inert and the dialog is exposed with modal semantics.
- Do not add `[tabindex]` to the `<dialog>` element.

<Callout type="info">
  Read the [MDN accessibility guidance for the `<dialog>` element](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog#accessibility) for more information.
</Callout>

#### Rounded corner

Rounded corner modals is a project-wide option therefore all your modal dialogs should either be rounded or not. Add `.use-rounded-corner-modal` on a top container (for example `<body>`) to use rounded corners.

<Callout type="warning">
  Rounded corners could be used in more emotional, immersive contexts or those tied to specific visual identities. **For standard or business-oriented usage, keep the default square corners.**
</Callout>

<Callout type="info">
  We use a `<div>` as a parent container because we cannot use `<body>` in an example.
</Callout>

### Close button

The close button may be hidden when the modal has a clear, visible alternative way to dismiss it, such as a single Cancel action or another explicit dismissal control. It may also be omitted when the modal represents a mandatory step in a controlled flow where dismissal is intentionally unavailable.

<Callout type="warning">
  The modal must always provide a discoverable and accessible way to close it.
</Callout>

### Actions layout

There can be up to three actions buttons on the modal. These buttons typically include a primary action, a secondary action, and an optional tertiary action, allowing users to confirm, cancel, or perform additional tasks related to the modal's content.

By default, the buttons will automatically stack vertically and grow to fill the available width on smaller screens.

<Callout type="info">
  As actions can be displayed in various ways depending on your needs, we rely on utility classes to achieve other layouts, such as [horizontal alignment](#horizontal-alignment) or [buttons that are not full-width on smaller screens](#no-full-width-buttons).
</Callout>

## Interactivity

In order to open a dialog, you need to use either [invoker commands](#invoker-commands) or [JavaScript](#javascript).

### Invoker commands

The Invoker Commands API provides a way to declaratively assign behaviors to buttons, allowing control of interactive elements when the button is enacted by the user. Please refer to the [MDN article on Invoker Commands](https://developer.mozilla.org/en-US/docs/Web/API/Invoker_Commands_API) for more information.

We use this method in the examples above to open and close the modal dialogs without writing any JavaScript code.

<Callout type="info">
  As Invoker Commands are only recently widely available in browsers, it is recommended to [integrate this polyfill](https://github.com/keithamus/invokers-polyfill) in your projects or use the [programmatic solution](#javascript).
</Callout>

First create a button with the `[commandfor]` attribute pointing to the ID of the modal dialog you want to control. The `[command]` attribute specifies the action to be performed, such as `show-modal` to open the dialog as a modal.

```html
<button type="button" commandfor="modalDialogInvokerCommand" command="show-modal">
  Open modal
</button>
```

Then create a `<dialog>` element with the corresponding ID that matches the `[commandfor]` attribute of the button.

```html
<dialog id="modalDialogInvokerCommand" class="modal-base modal-dialog" aria-labelledby="modalDialogInvokerCommandTitle">
  <h3 id="modalDialogInvokerCommandTitle" class="modal-title">Invoker modal dialog</h3>
  <!-- modal dialog content -->
</dialog>

```
Inside the `<dialog>` element, the buttons that should close the modal dialog need to have the `[commandfor]` attribute pointing to the ID of the dialog and the `[command]` attribute set to `close`.

```html
<button type="button" class="btn btn-close" commandfor="modalDialogInvokerCommand" command="close">
  <span class="visually-hidden">Close</span>
</button>
```
