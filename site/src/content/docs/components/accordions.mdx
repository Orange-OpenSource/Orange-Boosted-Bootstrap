Our accordions are based on our [items]([[docsref:/components/items]]). This is why they share the same structure, classes, and variants as items, with the addition of the interactive summary and expandable content specific to accordions.

### Approach

Accordions use native HTML `<details>` and `<summary>` elements. Activating the summary opens or closes the content without requiring the Collapse JavaScript plugin.

The accordions are based on our [items]([[docsref:/components/items]]) and follow a similar structure. The basic structure includes:

* `.item` and `.item-accordion` on the `<details>` element.
* `.item-container` and `.item-interactive` on the `<summary>` element.
* `.item-content` as the container for the summary content.
* `.item-text-container` as the container for the summary text.
* `.item-accordion-body` as a direct child of `<details>` for the expandable content. This is a slot where everything can be set as needed.

<Callout type="info">
  Our accordion items are based on a future proof architecture. For now it's missing:
  * some animations for the expand and collapse transitions on some browsers.
  * icons don't change when the accordion is expanded or collapsed on some browsers.
  * the grouping doesn't work properly on the older browsers.
</Callout>

### Accessibility

Use a clear, descriptive label in the `<summary>` so users can understand what content will be revealed. Native `<details>` and `<summary>` provide keyboard interaction and communicate the expanded or collapsed state without additional ARIA attributes.

<Callout type="info">
  Semantic tags must be used inside the `.item-accordion-body` to ensure proper structure and accessibility.
</Callout>

<Callout type="info" name="distance-in-components" />

<Callout type="danger" title="Interactive elements inside summary">
  Even if `<button>` or `<a>` or any interactive element is valid HTML inside `<details>`, it must not be used as child of `<summary>`. It's not valid from a functional point of view.
</Callout>

## [[comp]] Accordion card item

An accordion card item is a UI element shaped like a self-contained card that reveals or hides related content within the current context.

The accordion card item is used when a more prominent visual grouping is needed compared to an accordion list item. The card can be displayed on its own or as part of a card-based accordion collection, and may feature a distinct background, outline, or rounded corners.

Add `.item-accordion` to the `.item` `<details>` element and `.item-interactive` to its `<summary>` element. The available options are described in the [common variants section](#common-variants).

<Example buttonLabel="accordion card item" code={`<details class="item item-accordion">
    <summary class="item-container item-interactive">
      <span class="item-content">
        <span class="item-text-container">
          <span class="item-label">Label</span>
        </span>
      </span>
    </summary>
    <div class="item-accordion-body">
      <p class="mb-none">Accordion content</p> <!-- TODO: Or maybe it should be <p class="item-accordion-body"> ? Knowing that the slot must be <div> -->
    </div>
  </details>`} />

## [[comp]] Accordion faq

An accordion faq is a UI element designed as a row that accommodates a question-and-answer format, used to reveal or hide an answer within the current context.

Accordion faq are used to organize frequently asked questions into a compact, easy-to-scan list where users can open only the information they need. The question serves as the accordion trigger, and the related answer appears directly below when expanded.

Use `.item-list.item-accordion-faq` as the surrounding container and `.item-accordion` on each expandable item. The available options are described in the [common variants section](#common-variants).

<Callout type="info" title="Restricted options">
  Please note that the following options aren't suitable for [accordion faq](#accordion-faq):
  * Only the [leading icon](#icon) without size is allowed. It's the only option suitable for the leading container.
  * The [extra label](#text-container) and the [slot - label](#text-container) shouldn't be used in this context.
  * Only the [trailing text](#text) is allowed. It's the only option suitable for the trailing container.
  * [Outlined](#outlined) and [Rounded corners](#rounded-corners) shouldn't be used since the faq is considered to be always a list.
  * The [small size](#sizes) isn't suitable in this context.
</Callout>

<Example buttonLabel="accordion faq" code={`<div class="item-list item-accordion-faq">
    <details class="item item-accordion">
      <summary class="item-container item-interactive">

        </span>
      </summary>
      <div class="item-accordion-body">
        <p class="mb-none">Accordion content</p>
      </div>
    </details>

      </div>
    </details>
  </div>`} />

## [[comp]] Accordion list item

An accordion list item is a UI element shaped like a row, that reveals or hides related content within the current context.

Accordion items are typically stacked vertically, allowing users to scan sections and expand only the information they need.

Use `.item-list` as the surrounding container and `.item-accordion` on each expandable item. The available options are described in the [common variants section](#common-variants).

## Common variants

Accordions share item styles and can use the following options where appropriate for their content and context.

### With asset

The main container `.item-content` of an accordion item can contain up to 3 elements. They always appear in the following order:
1. [Leading container](#leading-container) (optional) using `.item-leading-container`
2. [Text container](#text-container) (required) using `.item-text-container`
3. [Trailing container](#trailing-container) (optional) using `.item-trailing-container`

#### Leading container

Use `.item-leading-container` to add content before the summary text, such as an icon or image.

</Callout>

#### Text container

There are 4 text elements that are meant to be used in the `.item-text-container`.

They always appear in the following order:
1. Overline (optional) using `.item-overline` (only if not [small accordion item](#sizes))
2. Label (required) using `.item-label`, that can optionally be bold (using `.fw-bold`)
3. Extra label (optional) using `.item-extra-label` (only if not [small accordion item](#sizes) or [accordion faq](#accordion-faq))
4. Description using (optional) `.item-description`

Optionally, a slot can be added at the end of the text container using `.item-slot` and/or in place of the `.item-label` (only if not in an [accordion faq](#accordion-faq)) if it replaces it.

<Callout type="info">
  Please note that you might want to apply one of our [color utility]([[docsref:/utilities/color]]) to the text elements (except the `.item-label`), to match the badge for example. Be sure not to convey information only through color.
</Callout>

#### Slots

All the slots are optional, but if one is used, it should be indicated via `.item-slot` on the slot container.

This component can contain many slots that can be used to add custom content. The main slots are located in the [leading container](#leading-container), the [text container](#text-container), and the [trailing container](#trailing-container). The slots are intended to be used for custom content that is not covered by the other elements of the component. We can add another slot outside of the `.item-content` container as well.

<Callout type="warning" title="Slot">
  The slot shouldn't contain any interactive element, since the `<summary>` itself is interactive.
</Callout>

<Callout type="warning" title="Small item">
  The slots shouldn't be used in a [small accordion item](#sizes).
</Callout>

Here is a small summary of the slots that can be used in an accordion item:
* [Leading container](#leading-container) using `.item-slot`
* [Text container](#text-container) using `.item-slot`
* [Trailing container](#trailing-container) using `.item-slot`
* A slot outside of the `.item-content` container, direct child of `.item-container` using `.item-slot`

### Events

You can listen for the `toggle` event on each `<details>` element to detect when an accordion is opened or closed.

```js
const accordionItem = document.querySelector('.accordion-item')
accordionItem.addEventListener('toggle', event => {
  if (event.target.open) {
    console.log('Accordion opened')
  } else {
    console.log('Accordion closed')
  }
})
```

### Programmatic control

Toggle accordion items programmatically using the `open` property:

```js
const accordionItem = document.querySelector('.accordion-item')

// Open the accordion
accordionItem.open = true

// Close the accordion
accordionItem.open = false

// Toggle the accordion
accordionItem.open = !accordionItem.open
```

For example, you can programmatically open all the accordion items in a group:

```js
const accordion = document.getElementById('accordionExpandCollapse')
const toggleBtn = document.getElementById('btnAccordionToggleAll')

if (accordion && toggleBtn) {
  const items = accordion.querySelectorAll('.accordion-item')
  const groupName = 'accordionExpandCollapse'

  toggleBtn.addEventListener('click', () => {
    const expand = toggleBtn.getAttribute('aria-expanded') !== 'true'

    for (const item of items) {
      if (expand) {
        item.removeAttribute('name')
        item.open = true
      } else {
        item.open = false
        item.setAttribute('name', groupName)
      }
    }

    toggleBtn.setAttribute('aria-expanded', String(expand))
    toggleBtn.textContent = expand ? 'Collapse all' : 'Expand all'
  })
}
```
